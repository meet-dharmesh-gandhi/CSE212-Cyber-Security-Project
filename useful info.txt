JSDoc:

    JSDoc is widely used in the industry for documenting JavaScript (and TypeScript) code. Below is a **proper industry-standard format** for JSDoc with examples for different use cases.

    ---

    ## **📌 JSDoc Standard Format**
    JSDoc comments always start with `/**` and use `@tags` to define metadata.

    ```js
    /**
    * Brief summary of what the function/class/module does.
    *
    * Detailed description (if needed). Can span multiple lines.
    *
    * @param {Type} paramName - Description of the parameter.
    * @returns {ReturnType} Description of the return value.
    * @throws {ErrorType} When the function encounters an issue.
    * @example
    * const result = myFunction(10);
    * console.log(result);
    */
    ```

    ---

    # **✅ JSDoc for Functions**
    ## **1️⃣ Documenting a Simple Function**
    ```js
    /**
    * Adds two numbers together.
    *
    * @param {number} a - First number.
    * @param {number} b - Second number.
    * @returns {number} The sum of `a` and `b`.
    * @example
    * const sum = add(2, 3);
    * console.log(sum); // 5
    */
    function add(a, b) {
        return a + b;
    }
    ```

    ---

    ## **2️⃣ Function with Optional and Default Parameters**
    ```js
    /**
    * Greets a user.
    *
    * @param {string} [name="Guest"] - The name of the user (optional, default is "Guest").
    * @returns {string} Greeting message.
    * @example
    * greet(); // "Hello, Guest!"
    * greet("Alice"); // "Hello, Alice!"
    */
    function greet(name = "Guest") {
        return `Hello, ${name}!`;
    }
    ```

    ---

    ## **3️⃣ Function with Multiple Parameter Types (`@param` with `|`)**
    ```js
    /**
    * Parses an input and returns a number.
    *
    * @param {string|number} input - The input to parse.
    * @returns {number} The parsed number.
    * @throws {TypeError} If the input is not a string or number.
    */
    function parseNumber(input) {
        if (typeof input !== "string" && typeof input !== "number") {
            throw new TypeError("Input must be a string or number.");
        }
        return Number(input);
    }
    ```

    ---

    # **✅ JSDoc for Objects & Classes**
    ## **4️⃣ Documenting an Object**
    ```js
    /**
    * Represents a user.
    *
    * @typedef {Object} User
    * @property {string} id - The user's unique identifier.
    * @property {string} name - The user's full name.
    * @property {string} email - The user's email address.
    */
    ```

    ✅ **Using the `User` typedef in a function**
    ```js
    /**
    * Creates a new user.
    *
    * @param {User} userData - The user details.
    * @returns {string} Confirmation message.
    */
    function createUser(userData) {
        return `User ${userData.name} created successfully.`;
    }
    ```

    ---

    ## **5️⃣ Documenting a Class**
    ```js
    /**
    * Represents a Person.
    */
    class Person {
        /**
        * Creates a new Person instance.
        *
        * @param {string} name - The person's name.
        * @param {number} age - The person's age.
        */
        constructor(name, age) {
            /** @private */ this._name = name;
            /** @protected */ this._age = age;
        }

        /**
        * Gets the person's name.
        *
        * @returns {string} The name of the person.
        */
        getName() {
            return this._name;
        }
    }
    ```

    ---

    # **✅ JSDoc for Async Functions & Promises**
    ## **6️⃣ Documenting an Async Function**
    ```js
    /**
    * Fetches user data from an API.
    *
    * @async
    * @param {string} userId - The ID of the user.
    * @returns {Promise<User>} A promise that resolves to the user data.
    * @throws {Error} If the user is not found.
    */
    async function fetchUser(userId) {
        const response = await fetch(`https://api.example.com/users/${userId}`);
        if (!response.ok) {
            throw new Error("User not found");
        }
        return response.json();
    }
    ```

    ---

    # **✅ JSDoc for Middleware & Express**
    ## **7️⃣ Documenting Express Middleware**
    ```js
    /**
    * Middleware to check if a user is authenticated.
    *
    * @param {import("express").Request} req - Express request object.
    * @param {import("express").Response} res - Express response object.
    * @param {import("express").NextFunction} next - Express next function.
    */
    function isAuthenticated(req, res, next) {
        if (!req.user) {
            return res.status(401).json({ error: "Unauthorized" });
        }
        next();
    }
    ```

    ---

    # **✅ Other Useful JSDoc Tags**
    ### **🛠️ Commonly Used JSDoc Tags**
    | Tag | Description |
    |------|------------|
    | `@param {Type} name` | Describes a function parameter |
    | `@returns {Type}` | Describes the return value |
    | `@throws {ErrorType}` | Describes possible exceptions |
    | `@example` | Provides a usage example |
    | `@typedef {Type} Name` | Defines a custom type |
    | `@async` | Marks an async function |
    | `@private` | Marks a property as private |
    | `@protected` | Marks a property as protected |

    ---

    ## **🚀 Industry Best Practices**
    ✔ **Keep descriptions short & clear**  
    ✔ **Use `@example` for complex functions**  
    ✔ **Use `@typedef` for reusable types**  
    ✔ **Use `@async` for async functions**  
    ✔ **Document error cases (`@throws`)**
